# How framerot works

[Back to the README](../README.md) · [User guide](guide.md) · [Build and validation](development.md)

This reference describes the current native implementation, its codec operations, limits and validation. For creative settings and installation, start with the README or user guide.

## Effects and controls

The **Effect** menu offers nine individual effects and Instrument for composition:

| Mode | Behavior | Useful settings |
|---|---|---|
| **Classic — keyframe loss** | Preserves the first I-frame, skips a configurable number of later I-frames, then lets a full keyframe restore the picture. | Classic skipped keyframes; keyframe interval |
| **Tear — periodic P-frame loss** | Discards every Nth predictive packet; later P-frames continue referencing a decoder with missing motion data. | P-frame interval |
| **Burst — packets lost in runs** | Discards the first *burst* predictive packets in each cycle; creates harsher temporal gaps and damaged references. | P-frame interval, burst length |
| **Echo — replay compressed motion** | Periodically substitutes an earlier compressed P-frame payload for a new one. It does not merely replay a rendered image. | P-frame interval |
| **Flow Drift — MPEG-4 motion vectors** | Requests real MPEG-4 block-motion vectors from the FFmpeg decoder, then uses them to warp/blend the previous decoded image along those paths. The encoded bitstream itself is not rewritten. | Motion exaggeration (0–500%), previous-frame persistence (0–100%) |
| **Motion Shimmer — P-frame rounding bit** | Flips the P-VOP motion-interpolation rounding bit directly in MPEG-4 packets generated by the filter. Doesn't change packet length or edit individual motion vectors. Can create subtle crawling or shimmer. | Shimmer: edit every N P-frames (1–60) |
| **Keyframe Anchor — reuse earlier I-frame** | Holds one genuine compressed I-frame for a configurable number of keyframe intervals while the encoder continues supplying current P-frames. Every few GOPs, it accepts a new I-frame and refreshes the anchor, creating temporal jumps and motion ghosts distinct from dropped keyframes. | Anchor: keyframes per held image (2–12); keyframe interval |
| **P-Frame Rewind — older compressed motion** | Remembers a fixed number of *original encoded P packets* in the current GOP, and replaces each new P with the compressed packet from N P frames earlier. Reset at each I-frame; unlike Echo, every eligible P uses an older packet, rather than occasional replay of the immediately previous one. | Rewind: P-frames back (2–12); keyframe interval |
| **Frame Peel — temporal bands** | Builds alternating horizontal bands from a rolling history of decoded MPEG-4 frames. The strips come from different moments, producing time-sliced tearing without arbitrary codec corruption. This is a decoded-image composition effect, **not** motion-vector/bitstream editing. | Peel: frames in history (2–8), band height (1–64 codec pixels) |

A mode change starts a new codec generation, including the initial decoder reference. Settings irrelevant to the selected preset are hidden.

### Instrument mode

New filters start in Instrument with a showcase combination: Cycle anchor (3 GOPs), live predictive packets, Packet editing (X 160%, Y 100%, residual strength 70%, block loss 10%) and Flow Drift (150% motion, 40% persistence). Codec height is 192px, 18 FPS, 320 kb/s and GOP 18, with 100% wet and live alpha preserved. Motion Shimmer and Frame Peel are available but off initially. Explicit saved selections take precedence; filters relying on old implicit defaults may inherit the new defaults. This is a deliberately chosen creative starting point, not a guarantee of a particular look for every source.


Choose **Instrument** to combine a reference-frame operation (live, skip or cycle anchor), a predictive packet operation (live, tear, burst, echo or rewind), and independent Shimmer, Flow Drift, Frame Peel and compressed vector/residual editing layers. Packet operations precede decoding; Peel then Flow run on decoded pixels. The nine individual presets are shortcuts to individual operations.

Only the controls for active reference, predictive and layer operations appear. Disabling an operation hides its sliders without losing their values. In Instrument, **Load starting point** offers three editable combinations: Memory Melt (cycling anchor and compressed edits), Motion Smear (compressed motion and decoded motion feedback), and Time Ribbons (packet echo and temporal bands). Selecting one explicitly replaces the effect and codec settings, preserves wet mix and alpha, and returns the selector to Custom so later adjustments are not overwritten. These are creative starting points, not separate codec algorithms.

**Randomize (experimental)** in the same starting-point menu generates a fresh, editable combination when selected. It chooses one or two non-conflicting operations, with 144/192/288px codec height, 12–24 FPS, 160–650 kb/s, GOP 12–24, limited keyframe suppression, motion delta −150% to 250%, residual strength 30–110% and residual loss 0–30%. Burst size cannot exceed half its packet interval; rewind depth fits within the GOP. It never changes wet mix or alpha or continuously rerolls during rendering. Choose it again for another roll; the resulting settings are saved normally. Bounds reduce risk, not a guarantee of crash-free operation, pleasing output or broadcast performance.

**Compressed editing** parses and rebuilds our own MPEG-4 Simple Profile P-VOP macroblocks, including variable-length motion-delta and run/level coefficient codes. Horizontal and vertical motion deltas support signed scaling (−500% to 500%); inter residual coefficients support signed scaling (−200% to 200%), and residual block loss (0–100%) selectively removes coded residual blocks. Neutral values (100%, 100%, 100%, 0%) leave the packet unchanged. These controls update live without resetting the held reference. Unsupported packet syntax is left unchanged. This is not an arbitrary MPEG-4 file editor or absolute motion-vector field scaling.

**Hold reference** reuses the last admitted or captured compressed I-frame on subsequent keyframe boundaries; **Release reference** forces a new clean I-frame on the next processed input. **Reset codec and history** starts a fresh generation and releases hold. OBS source hotkeys are registered for momentary hold and reset; button hold is latched until released.

**Codec height** (64–576 pixels, 16-pixel steps), **Wet mix** (0–100%), and **Preserve live source alpha** are independent. At 100% wet with alpha preservation disabled, non-capture renders draw the cached decoded texture without a new full-size source capture. With alpha preservation enabled (default), current source alpha is composited with the decoded RGB; alpha itself is not datamoshed. HDR framebuffer rendering bypasses the SDR codec path rather than claiming HDR effects.

### Showcase defaults

Each effect supplies its own deliberately useful starting settings rather than inheriting Classic's 96 kb/s, 12 FPS and 6-frame GOP. Selecting an effect updates only **OBS default values**; manually adjusted or explicitly saved values take precedence. This also applies when reopening saved scene filters: a saved mode receives its mode-appropriate defaults for settings that were never explicitly set.

| Effect | Codec FPS | Bitrate (kb/s) | Keyframe interval | Effect-specific showcase setting |
|---|---:|---:|---:|---|
| Classic | 12 | 96 | 6 | Skip 1 keyframe |
| Tear | 15 | 160 | 12 | Every 5th P-frame |
| Burst | 15 | 160 | 18 | 5 P-frames lost per 12-frame interval |
| Echo | 15 | 160 | 18 | Replay every 3rd P-frame |
| Flow Drift | 15 | 230 | 24 | Exaggeration 250%, persistence 65% |
| Motion Shimmer | 15 | 200 | 24 | Edit every P-frame (interval 1) |
| Keyframe Anchor | 15 | 160 | 12 | Hold anchor for 4 keyframes |
| P-Frame Rewind | 15 | 220 | 24 | Rewind 4 P-frames |
| Frame Peel | 15 | 200 | 18 | 4-frame history, 12px bands |

This intentionally does **not** reset a scene's existing user-entered fields when choosing another effect. A user may retain a custom codec frame rate or bitrate across mode changes; new filters or untouched fields use the recommended settings.



Flow Drift exports the codec's genuine motion-vector side data (not optical flow or a shader-generated field). It uses a motion-block CPU compositing pass, so it behaves differently from packet suppression. Setting either Flow parameter to zero removes the Flow contribution; other enabled operations still apply. Pacing/performance should still be tested in normal OBS before heavy streaming.

Motion Shimmer has a bounded parser for **our own MPEG-4 Simple Profile P-VOP packets**, not arbitrary video. It verifies marker bits and nonzero quantizer/fcode values before editing a single bit, and otherwise leaves the packet unchanged. Tests of our generated stream at 12, 15, and 30 FPS successfully decoded all frames. The effect is relatively gentle; the separate compressed editing layer rewrites motion deltas and residuals.

P-Frame Rewind stores at most 12 compressed P packets and resets its history at each keyframe. A short keyframe interval relative to the rewind depth may leave few eligible P-frames; the preset uses GOP 24 and depth 4. Frame Peel keeps at most 8 decoded RGBA frames and caps its allocation at 32 MiB. In the individual Frame Peel preset the default internal height is 144px; its band-height setting refers to that codec resolution, not full OBS output pixels. Both effects preserve the OBS source geometry.

Keyframe Anchor only stores one compressed I packet, bounded to the same codec configuration. The initial I-frame establishes the reference. For a noticeable effect, try GOP 9–18, anchor span 4–8, and moving footage with hard scene changes. The encoder and decoder continue running normally, with no change to the source's dimensions.

Common settings: **Keyframe interval** (2–120 frames), **Bitrate** (8–2000 kb/s), and **Codec frame rate** (1–30 FPS). The filter repeats the last decoded output between processing ticks. Instrument is the default effect. Classic remains available in the Effect menu. This is MPEG-4 Part 2 processing, not a claim of duplicating Datamosher Pro's entire effect collection.

## OBS scene transforms and projection safety

Datamosh is an **OBS video filter**, not a scene-transform replacement. Its output dimensions remain the size of the filtered source; a 640×480 camera remains 640×480 unless its scene item is scaled by OBS or a dedicated rescale filter. The internal MPEG-4 low-resolution frames are upscaled **inside that source frame**, not to the entire OBS canvas.

**Fixed in v0.4.1:** The filter used to call gs_ortho() while presenting its final image and never restore the caller's projection. When a camera's native dimensions differed from the scene canvas, this could cause a wrong bounding box, transform misalignment, and displaced subsequent scene elements. The final draw now uses OBS's active source projection, and the two offscreen conversion passes balance their temporary projections with gs_projection_push() / gs_projection_pop().

The native OBS regression covers both a transformed 256×144 source inside a 640×360 canvas and the originally observed **640×480 source inside a 1920×1080 canvas**. It checks a colored source region, empty regions outside the source bounds, and an independent scene marker drawn after the filter. The old installed v0.4.0 module failed those checks; the patched build passes. This is stronger than an edge-fill-only test, but it does not prove unrelated user camera/source configuration or all OBS plugins.

## Source size and aspect ratio

The filter **renders back over the entire filtered source**, preserving its original dimensions and avoiding the old 4:3 crop and side/top/bottom black bars. For speed, the encoded picture remains low resolution: 192 pixels high by default in Instrument (144 in the individual presets) with a width rounded to a valid MPEG-4 macroblock boundary based on the input source aspect ratio, capped at 1024 pixels wide.

Examples: at the 144px height setting, a 1920×1080 source is processed at 256×144 internally, a 640×480 source at 192×144, and a 1080×1920 source at 80×144. Decoded output is stretched over the source dimensions, so extreme aspect ratios may introduce modest distortion from macroblock rounding. The internal codec quality and GPU readback cost differ from the full-resolution OBS output. The codec itself produces opaque RGB; the optional live-alpha composite preserves the original coverage.

## Boundaries

This implementation includes **MPEG-4 I-frame skipping, P-frame loss, burst loss, compressed P-frame replay/rewind, compressed I-frame anchoring, motion-vector-driven feedback, temporal-band peeling, a one-bit P-VOP motion interpolation rewrite, and bounded P-VOP motion-delta and inter-residual rewriting**. It does **not** yet implement arbitrary external video stream editing, absolute motion-vector field transforms, the full Datamosher Pro effect list, or recording-file mosh workflows.

The encoder/decoder run on a portable C++17 bounded per-filter worker (one pending input, one in-flight input, latest output). GPU staging is deferred: the next render maps the previous staged frame; a graphics driver may still block on the map. The output texture is drawn directly at source dimensions. Codec and readback timing, dropped inputs, errors, recoveries and compressed edit counts are logged when a configuration is retired. Render callback mean and maximum CPU duration are logged on filter destruction. Tests cover actual packet differences, all preset paths and the Instrument composition, codec P-VOP header editing at multiple frame rates, decoder-exported motion vectors, zero-strength behavior, property visibility, live mode switching, landscape/portrait rendering, alpha and a two-filter stack exercising Classic, Flow Drift and Instrument, and scene projection safety under source/canvas size mismatch, but *not* sustained low-latency 1080p60 streaming, other graphics backends, or cross-platform builds. The optional synthetic 1080p60 desktop diagnostic is not a sustained broadcast test. The low internal resolution reduces codec work, not necessarily GPU readback stalls.

On decoding failures the filter passes through the captured source until fresh output is available. The worker discards its failed codec state and retries on incoming frames no more frequently than every 250 ms; fresh output resumes the effect.
